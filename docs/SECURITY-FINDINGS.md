# Security Findings — Responsible Disclosure Log

**This file is not part of the application. It is never read, referenced,
or shipped by any code in this project.** It exists purely as a
human-readable record for the maintainer to use for responsible
disclosure to the actual owners/maintainers of any contract a finding
concerns.

## Ground rules for this file (read before adding anything)

- **Findings only, never exploit code.** A description of what looks
  wrong and why is appropriate. A working proof-of-concept transaction,
  crafted calldata designed to trigger the issue, or step-by-step
  instructions sufficient to reproduce a drain/exploit are NOT — those
  don't belong here, in this codebase, or anywhere in this project.
- **No automated detection logic lives in the app.** Explorer (and any
  other app in this project) surfaces real, public information — real
  entrypoints, real activity signals, real holdings — the same category
  of thing any block explorer shows. It does not scan for, flag, or
  auto-generate anything related to a specific vulnerability class.
  Anything that looks like a real bug, found incidentally while using
  the device normally, gets written down *here*, by a human, not
  surfaced as an in-app feature.
- **The goal is disclosure, not exploitation.** An entry here should be
  written the way you'd write it in an email to the project's team —
  what you saw, why it concerns you, and enough detail for them to
  investigate and fix it. Not enough detail for someone else reading
  this file to act on it themselves.
- **When in doubt, say less.** A vague-but-accurate description that
  prompts the actual maintainers to look closer is more responsible
  than a precise one that could be misused by whoever else sees this
  file.
